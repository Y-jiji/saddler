---
name: fileguard
description: sandbox Bash, give every session and subagent its own view of this project, and publish their commits as branches
disable-model-invocation: true
---

Do these in order:
1. Check `bwrap`, `flock`, `setsid`, `nsenter`, `git` and `python3` are on `PATH`; if any is missing, stop and tell the user.
2. From this skill's directory, copy `sandbox.sh`, `allowlist.sh`, `overlayfork.sh`, `checkpoint.sh` and `requestcheckpoint.sh` to `~/.claude/saddler/`, and `whitelist.txt` to `~/.claude/sandbox/` unless that file already exists.
3. Add `"env": {"CLAUDE_CODE_SHELL_PREFIX": "<absolute path of ~/.claude/saddler/sandbox.sh>"}` to `~/.claude/settings.json`.
4. From this skill's directory, copy `sessionstartsandbox.py` and `pretoolusewrite.py` into `<project>/.claude/hooks/`.
5. Register in `<project>/.claude/settings.json`. `<session>` is `python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/sessionstartsandbox.py"` and `<guard>` is `python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/pretoolusewrite.py" || exit 2`:
   - SessionStart: `<session>`, timeout 10
   - PreToolUse, matcher `Agent|Bash|Monitor|Write|Edit|NotebookEdit|Read|Grep|Glob`: `<guard>`, timeout 110
   - Optional: `"env": {"SADDLER_BUILD": "<build command>", "SADDLER_PREEMPT_WAIT": "60"}`. `git checkpoint` runs the build command in the agent's view, and a checkpoint gives running commands the wait, in seconds, before it kills them; 60 is the default. Keep the wait under 100, because a command the checkpoint waits for can hit the Bash tool's timeout.
6. Inline every line of `PROMPT.md` from this skill's directory into `<project>/CLAUDE.md`, creating it if missing and skipping lines already there. Copy exact lines and ONLY from it. Do not invent. Do not copy the file into the project, do not add `@PROMPT.md`.
7. Tell the user to restart claude, then check in the new session: `echo x > .claude/x` fails with `Read-only file system`, `ls /run` fails, `echo x > f` leaves the real `f` unchanged, a commit lands on branch `session-<session-id>/agent-master` once its command ends, a subagent's commit lands on `session-<session-id>/agent-<agent-id>`, Read and Grep are refused, and, if `env` is set, `echo $SADDLER_BUILD` prints its value.

Why:
- Every session's main agent and every subagent works on its own view of the project: an overlay whose lower is the real project folder, tracked and ignored files alike, and whose upper is private. Nothing an agent writes reaches the real files except through `git checkpoint`.
- Each view has a privatized `.git`: its own HEAD, index, refs and config, which includes the real repository's config, and a folder that stages new objects. It reads the real objects through git alternates, and sees the real branches, read-only and always current, as `saddler/<branch>`. The real `.git` is read-only to every agent.
- After each command, the agent's branch is published to `session-<session-id>/agent-<agent-id>`: new objects first, checked by `unpack-objects --strict`, then the branch. A branch that drops a commit the default branch has is not published. Agents commit, branch, stash and rebase on their own; nothing merges automatically.
- `git checkpoint`, an alias in every view, makes the agent's branch everyone's base. With a clean tree whose HEAD the default branch can fast-forward to, it runs `SADDLER_BUILD` in the view, and a failed build stops it. When the command ends, `checkpoint.sh` makes new commands fail, gives running commands `SADDLER_PREEMPT_WAIT` seconds, then kills every holder. It saves changes made straight in the real project to a `rescue-<time>` branch, fast-forwards the default branch, moves the agent's upper into the real folder, and leaves the real HEAD on the default branch. It then publishes every other agent once, deletes every agent's view, deletes agent branches the default branch has, and prunes objects nothing reaches. Every agent's next command starts over from its branch on the new base, and its uncommitted work is gone.
- The real files change only at a checkpoint, so your terminal sees the last one. Edits you make there to tracked files show up in every view, make `git checkpoint` refuse in views that see them, and are saved to a rescue branch and replaced at the next checkpoint. Between checkpoints nothing prunes the real objects (`gc.pruneExpire=never`), and refs stay loose (`gc.packRefs=false`) so views see them.
- Read, Write, Edit, NotebookEdit, Grep and Glob are refused in a project with a commit. Claude Code runs them outside the sandbox, on the real project, and a path rewritten to `/proc/<holder>/root` does not survive its path resolution. Use Bash: `cat`, `sed`, `rg`, `find` and heredocs. Images and PDFs cannot be read there.
- One holder process per agent, with a PID namespace, keeps its view mounted, so foreground and background commands share one mount. A holder dies with its Claude process and at every checkpoint; its next command starts a new one. Holders are recorded with their start time, so a reused PID counts as dead and is never killed. A finished subagent's view stays until the next checkpoint, so a resumed subagent finds its uncommitted work.
- The first command in a project records its HEAD as the base, if its tracked files are committed. A project without a commit runs commands in the plain sandbox, on the real files.
- `allowlist.sh` runs a command in bwrap on an empty root holding only the host `/dev`, a fresh `/proc`, every library and `PATH` directory read-only, every dot entry in `~` read-only, the entries of `whitelist.txt`, and the project, with every `.claude` read-only.
- `whitelist.txt` is the global registry: one `ro PATH`, `rw PATH` or `private PATH STORE` per line, `~` expanded, missing paths skipped. `private` makes `PATH` writable into `STORE`, with its real entries read-only inside, so ssh can keep ControlMaster sockets in `~/.ssh`. Only download caches are writable, because a sandboxed command could otherwise replace programs you run outside the sandbox.
- State lives in `~/.claude/sandbox/project-<percent-encoded project folder>/`: `lock/` with the base, the generation, the gate, the checkpoint lock and one registration per agent; `realgit`, a link to the real `.git`; `uppersize.log`, each upper's new largest size per generation; and `session-<session-id>/agent-<agent-id>/{fork, work, git}`. A session without its folder runs unsandboxed. `SessionStart` makes it, and `pretoolusewrite.py` makes it in print mode, where `SessionStart` does not fire.
- Claude Code's wrapper format is undocumented and tool calls are told from hook shells by it, so repeat the step 7 checks after updating Claude Code.
- Steps 2 and 3 come before step 5: once `pretoolusewrite.py` is registered, Write cannot reach `~/.claude`; once the prefix is live, neither can Bash.
- A session or project on the old hooks runs unguarded under this `sandbox.sh`: run `migrate.py <folder> --apply` outside the sandbox and restart every session. It scans the folder for `.claude`, compares each project's hook entries and hook files with the current ones, and fixes what differs.
- `|| exit 2` denies the call if the guard is broken, instead of running it unguarded.
